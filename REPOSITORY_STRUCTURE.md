# Repository Structure

```
partnership-outreach-system/
├── README.md                                  # Purpose, system of record, operating principles
├── REPOSITORY_STRUCTURE.md                    # This file
├── PROJECT_GOAL_AND_CLAUDE_INSTRUCTIONS.md    # Claude Project description + instructions
├── SETUP_AND_EXECUTION_CHECKLIST.md           # Full action plan, setup to delivery
├── STARTER_PROMPTS.md                         # Sequential prompts for Claude
├── TRACKER_COLUMNS.md                         # ClickUp tracker columns + statuses
├── 01-brand-profiles/
│   └── pirate-gold-poker.md                   # Brand facts (verified vs. to-confirm)
├── 02-research-criteria/
│   └── creator-qualification.md               # Hard checks, /25 scoring, required evidence
├── 03-taste-and-voice/
│   └── outreach-style-guide.md                # Voice principles + pre-send check
├── 04-outreach-templates/                     # From Iyah's Outreach Playbook v2 (Oct 2026)
│   ├── instagram-dm.md                        # DM 1 collab pitch · DM 2 seasonal · DM 3 after yes · DM 4 follow-up
│   ├── email-templates.md                     # Email 1 personal pitch · 2 proof-led · 3 IG→email · 4 business/event · 5 concept pitch
│   └── follow-up.md                           # Follow-up 1 (new detail) · Follow-up 2 (short reminder)
├── 05-playbooks/
│   └── creator-outreach-sop.md                # Step-by-step research & outreach SOP
├── 06-quality-control/
│   └── verification-checklist.md              # Final QA before submission/outreach
└── 07-learnings/
    └── experiment-log.md                      # Validated lessons and rule updates
```

**Reusable vs. campaign-specific:** `01-brand-profiles/` holds brand-specific facts (one file per brand). Everything else is a reusable standard. Live lead and outreach data lives in the tracker, not in this repo.
